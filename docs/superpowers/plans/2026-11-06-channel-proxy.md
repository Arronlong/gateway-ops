# 渠道全局代理实现计划

目标：在渠道新增或编辑表单中选择全局 HTTP/HTTPS 代理，新增代理只填写完整 URL，渠道后续上游请求使用该代理。

设计：代理独立存储，完整 URL 加密保存，接口只返回脱敏地址；渠道保存可空代理 ID。请求上下文携带代理，连接池按照代理隔离，避免并发渠道互相影响。原有渠道默认保持原请求行为。

实现顺序：

- [x] 补充全局代理保存、校验、跨渠道复用、切换和清除的后端测试。
- [x] 补充两个连接器实际经过认证代理、并发隔离和渠道测智使用代理的测试。
- [x] 实现代理表与接口、渠道引用、连接器请求和渠道测智的代理传递。
- [x] 渠道表单站点地址下方增加代理选择与单输入框新增，新增后自动选用。
- [x] 运行定向测试、后端回归、前端类型检查与构建，检查实际页面交互。
- [x] 检查编码与差异，完成独立本地提交。

验收：在任意渠道新建代理后可在其他渠道选用；保存并重开后选择正确；可恢复不使用代理；无效代理被拒绝；认证信息不回显；实际 HTTP/HTTPS 上游调用经过对应代理。

验证记录：后端全量测试、前端原生 Node 测试、TypeScript 类型检查、前端生产构建和后端构建均通过。浏览器验收使用真实渠道表单组件并拦截 API，不修改现有渠道、不新增真实代理或发送付费请求；覆盖手动与自动余额渠道、全局复用、动态新增自动选择、保存回显、清除、无效协议、取消与 390 像素宽度。

代理范围：登录、会话校验、Token 刷新、余额、倍率、用量采集、用量核对、历史起点查询、渠道测智出站。第三方打码服务及中转站管理 API 仍使用各自原有连接，避免越过渠道边界。

兼容：未选择代理的旧渠道保持原有连接行为；已选代理不可用时返回错误，不绕过代理直连。省略 proxy_id 保留绑定，null 或 0 清除绑定。完整 URL 在数据库中加密保存，接口只返回脱敏地址；相同 URL 新增去重。

关联测智边界：从中转站复用渠道测智 Key 时一并保留来源渠道，并继承其代理；相同 Key 对应多个不同代理时要求从对应渠道发起。测智分组元数据查询使用每个会话所属渠道的代理，不能继承生成目标或其他渠道的代理。相关测试同时验证两个不同出口和间接测智调用。

并行改动保护：最终后端全量回归在只含本次暂存内容的独立代码副本中运行并通过。工作区其他任务的分组快照等改动不纳入本次提交；共用 storage.go 仅暂存本功能的 ProxyConfig 迁移条目。
