# 渠道历史用量分层校验与定向修复计划

**目标：** 自动校验和手动重拉共用月、周、天分层比较，仅抓取异常日期，限制上游请求频率。

## 功能单元一：轻量统计与上游保护

- 连接器使用同站点共享限速，403/429 后冷却，支持取消。
- sub2api 完整 UTC 日期读取 total；部分日期用排序分页二分边界，不再全量遍历。
- 缺少可信统计元数据时报告无法校验，不退回全量抓取。
- 先补充定向测试并确认失败，再实现和提交。

## 功能单元二：分层校验与定向重拉

- 复用现有账号认证、用量仓库和 SSE；月一致跳过，异常月分周，异常周分天。
- 异常日期才分页拉取，条数验证完整后事务替换对应账号和日期，失败保留原数据。
- 自动任务以轻量条数统计定位全部留存历史，每轮最多校验三个月份，持久保存进度，完整校验后每天重新检查。
- 手动支持自定义和全部，不推进增量游标；进度显示跳过、异常和修复情况。
- 验证跨月、跨周、无数据、多账号、统计不可用、部分失败、进度恢复和取消，再跑受影响包与全量回归。

**边界：** 不调用真实上游做回补测试，不触发付费模型，未经要求不重启服务。

## 已完成的验证

- 后端全量 `go test ./... -count=1` 和受影响包 `go vet` 通过。
- 前端 240 项测试、TypeScript 类型检查和生产构建通过。
- 画册、列表两种模式，1440/390 宽度下的历史弹窗、自定义区间、重拉进度与刷新均通过模拟接口浏览器验证。
- 使用临时 SQLite 和 `httptest` 验证跨月、多账号、全部历史终止、完全缺失旧月份、失败保留、取消和自动断点恢复。

**运行策略：** 同一上游的用量请求串行，至少间隔 500ms；403/429 后冷却 10 分钟。增量同步与历史校验的进度独立，历史异常不阻断近期增量。
