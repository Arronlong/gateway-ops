# 渠道编辑中的中转站账号关联设计

## 目标

让用户在“编辑渠道”弹窗内直接查看和修改渠道账号与中转站账号的关联关系，避免必须从渠道卡片外部寻找隐藏入口。

本次只补齐前端入口和编辑体验，不改变现有关联数据模型、关联接口或筛选语义：

- 编辑已有渠道时显示“中转站账号关联”区域。
- 新增渠道时不显示该区域，因为渠道账号尚未创建，无法建立关联。
- 关联粒度仍为“渠道账号 + 中转站 + 中转站账号”。渠道列表筛选只聚合到中转站粒度。
- 中转站账号被删除后，由后端重建关联快照时清理失效链接，前端刷新后显示为“未关联”。

## 根因

当前代码已经具备以下能力：

- `GET /channels/associations` 返回中转站、账号和渠道关联快照。
- `PUT /channels/:id/accounts/:account_id/relay-links/:station_id` 保存自动、手动或未关联状态。
- `ChannelAssociationDialog` 已实现账号级关联选择。
- 渠道筛选已按关联快照聚合“具体中转站”和“未关联”。

但 `ChannelAssociationDialog`、`AssociationStatusButton` 以及 `associating` 状态没有挂载到可见的渠道编辑流程中，导致功能代码存在但用户无法进入。

## 方案选择

采用“抽取关联编辑区域并嵌入 `ChannelFormDialog`”的方案。

1. **嵌入编辑弹窗，推荐**：用户点击编辑渠道后，在同一个弹窗内完成渠道信息和中转站账号关联；不新增额外入口，符合用户对编辑功能的预期。
2. **继续使用独立关联弹窗**：只在渠道卡片增加独立关联按钮。改动较小，但用户仍可能认为编辑功能缺失，且与本次诉求不一致。
3. **把关联字段并入渠道 API 主体**：由渠道保存接口同时提交关联关系。会扩大保存接口职责，并增加账号新增、删除和关联同步的耦合，本次不采用。

## 前端结构

新增可复用组件 `ChannelRelayAssociationEditor`，负责：

- 接收当前渠道、关联快照和刷新回调。
- 按渠道账号展示各中转站的当前状态。
- 支持“自动关联”“手动未关联”和选择具体中转站账号。
- 调用现有关联 PUT 接口，成功后重新读取关联快照。
- 显示自动关联、手动关联、自动未匹配和手动未关联状态。

`ChannelFormDialog` 新增可选关联相关属性，仅在编辑模式下渲染该组件。父级 `ChannelCards` 复用已有的 `useChannelRelayAssociations` 请求，避免表单打开后产生重复快照请求。

删除或迁移当前未挂载的 `ChannelAssociationDialog`、`AssociationStatusButton` 和对应的无效状态，避免保留两套入口逻辑。

## 数据刷新与删除行为

- 关联选择成功后刷新 `/channels/associations`，编辑弹窗中的状态和渠道列表筛选同时更新。
- 关联快照接口执行后端 reconcile：当中转站账号不存在时，自动链接会被清理；手动链接若指向不存在账号也会被清理。因此该渠道在列表筛选中不再命中具体中转站，而会落入“未关联”。
- 删除整个中转站时，现有存储事务会删除该中转站的渠道关联链接；下一次快照刷新后同样显示为未关联。

## 兼容性与边界

- 不修改数据库迁移和后端 API。
- 不把关联关系写入渠道编辑主体保存 payload，关联更新仍然即时生效。
- 新增渠道保存成功后，用户可重新打开编辑弹窗设置关联。
- 没有中转站时显示空状态；没有关联账号时可选择“手动未关联”。

## 验证

- TypeScript/Vite 构建通过。
- 前端静态检查确认编辑弹窗包含关联区域，新增弹窗不包含关联区域。
- 手动选择中转站账号后，重新读取快照并能按该中转站筛选。
- 删除或失效中转站账号后，重新读取快照不再命中该中转站，并能被“未关联”筛选命中。
