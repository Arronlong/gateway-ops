# 缓存观测与中转站链路测试设计

工作分支：`codex/cache-relay-history`，基于 `main` 的 `6f19904`。用户已授权自主决策并实现。

## 统计窗口

每个渠道和中转账号独立统计：先取最近 1 小时的记录，再按时间倒序取最近 60 次。不从一小时以前补齐。忽略无效和未来时间。两个指标使用同一个样本窗口，不受页面大范围筛选影响。

缓存命中率以请求为单位：缓存读取 token 大于 0 的次数，除以缓存状态已知的次数。同时在提示中展示读取 token 总量。不用各平台不一致的输入 token 口径作为命中率分母。

成功率：成功次数除以结果已知次数。展示有效样本数。未知状态显示暂无数据；未知不算成功或失败。NewAPI 同步消费与错误日志，其他日志不进入窗口。Sub2API 账号日志未提供失败状态时不伪装全成功。

中转账号从本地用量表直接读取最新60次调用，并按站点和账号匹配。后台补采的记录在页面刷新后即可统计。

## 展示

使用蓝色缓存命中和绿色成功率圆环，并展示窗口内样本数。卡片与列表均可见，悬浮或聚焦显示口径和数据新鲜度。

## 测试历史

一次账号或分组测试为一个批次。每个中转站共保留最近 30 批次，成功、失败和前置配置错误都归档。保存测试时间、目标快照、模型、模式、每次调用状态、耗时和脱敏输出。站点删除时清理历史。

写入和裁剪在同一事务中，对站点行加锁防止并发超过 30 条。列表仅显示最新结果，点击打开左侧时间轴、右侧 SVG 详情。SVG 按每批结果重建，保持矢量和动态连线，支持下载。不伪造上游不提供的内部跳点。
