# New API 中转站管理设计

目标：在现有中转站管理中接入 New API 的完整管理流程，保留 Sub2API 的行为和数据。

1. 站点增加 `type`，旧数据默认 `sub2api`；新建站点支持 `newapi`。
2. New API 支持管理员账号密码、访问令牌与 Cookie 会话。凭据加密保存，接口仅返回配置状态。管理员会话按站点和凭据独立缓存，失效后重新登录。
3. 管理适配器将 New API 渠道映射为调度账号，分组名称转换为稳定的本地外部标识。快照、成本绑定、调组建议、调度状态及审计复用现有流程。
4. 接入渠道读取与修改、渠道删除、渠道复制、分组倍率、用户列表与状态、用户删除、消费日志、模型列表、真实渠道及分组测试。
5. New API 分组倍率通过全局配置写回，需要 root 权限。字段不具备对应上游语义时，返回明确能力错误；保留原生管理能力，避免伪造成功。
6. New API 原生优先级数值越大越优先，适配成现有分析采用的优先级顺序。并发和池重试等 Sub2API 字段不映射为无关字段。
7. 用量通过 `quota_per_unit` 换算，错误日志保留失败状态；缺失成本不冒充零成本。
8. New API 渠道密钥读取需要绑定渠道的一次性安全证明，且用量接口不返回令牌的实际分组；后台不得自动读取或推断成本。探测状态标记为需手工配置，成本通过渠道关联或手工倍率维护。
9. 站点管理凭据仅通过 HTTPS 发送；本机回环 HTTP 仅用于开发测试。
10. 测试覆盖鉴权、分页、分组稳定标识、写操作、用量换算、安全限制、错误与 Sub2API 回归。
