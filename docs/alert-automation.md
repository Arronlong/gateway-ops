# 预警中心与自动化

预警中心复用现有页面外壳，标题位于第一行，四个指标卡位于第二行，第三行通过「预警事件」「订阅规则」「通知渠道」「发送记录」切换列表。入口为 `/alerts`，旧入口 `/notifications` 继续可用。

## 规则对象与判定

账号规则只监控中转站里的 `RelayAccount`。渠道登录账号 `ChannelAccount` 只提供关联余额，不作为独立预警对象。用户规则监控中转站用户。

| 规则 | 判定方式 |
| --- | --- |
| 倍率变化 | 相对最近正常倍率的百分比或绝对差值，支持上涨、下跌或双向；异常期间冻结基线 |
| 渠道余额低 | 取关联渠道账号最低有效余额，小于或等于阈值时命中；任一关联余额不可用时不做自动化判定 |
| 账号消耗异常 | 窗口内累计账号成本达到阈值；可进一步要求达到历史同窗口均值的指定倍数 |
| 账号稳定性异常 | 错误率、首字耗时 P95、请求耗时 P95 或连续请求失败数 |
| 用户消耗异常 | 窗口内用户实际扣费达到阈值，可叠加历史基线条件 |
| 用户多 IP | 窗口内不同来源地址达到阈值，支持 IPv4、IPv6、可信 IP 和 CIDR |

消耗与 IP 规则可以配置最少请求数。历史基线取最近 7 天相同时间窗口的平均值，至少需要 3 个完整历史窗口。账号成本优先使用上游返回的账号成本，否则使用请求原价乘以账号成本倍率；缺失成本信息时不猜测金额。用户消耗使用用户实际扣费。

触发条件支持两种计数：

- 连续 N 个有效采样命中，默认 N 为 3。
- 最近 M 个有效采样中至少命中 N 次，M 不能小于 N。

恢复可以配置独立阈值与连续次数，默认连续正常 3 次。余额恢复阈值应高于触发阈值，其他指标的恢复阈值应低于触发阈值。叠加历史基线后，仍须满足明确配置的恢复阈值。

缺失、过期、不完整的数据不作为正常数据，不触发自动恢复；重复或倒退的采样时间不增加次数。无活动事件时修改判定会重新累计证据；存在活动事件时仅允许调整名称、通知、冷却、备注和启用状态。

## 自动化处理

每条规则可以选择仅记录和通知，或配置一种自动化动作：

- 自动停止账号调度。
- 自动恢复账号调度。
- 自动停用用户。
- 自动启用用户。

停用动作可以开启条件恢复后的自动恢复，也可以保持「无自动恢复」。启用动作不自动反向停用。指定自动化目标时使用中转站远端数字 ID，不能使用邮箱；指定 ID 时只允许选择一个中转站，避免不同站点的同号对象混淆。

自动恢复仅作用于本事件成功停用的对象，同时检查当前状态、远端版本指纹、人工介入标记和其他规则的停用约束。对象原本已经停用时不取得恢复所有权；人工操作、状态版本变化或其他规则仍要求停用时，不擅自启用。

执行前记录动作占位，防止并发、重启或超时导致重复写入。结果不确定的写请求不自动重放，执行记录会提示人工核对。人工调度和用户状态操作与评估共用锁，同状态的人工操作也会阻止本事件随后自动恢复。

「确认」只标记已查看；「关闭」只结束事件，保留远端状态。暂停规则后停止该规则的评估与自动恢复，已有停用状态需要人工关注。存在未恢复事件时不能删除规则。

## 消息通知

消息正文全部内置，无须配置模板。内容包括规则、级别、对象、指标、实际值、阈值、窗口、触发时间、判定摘要、自动化结果与事件详情路径。规则可以选择现有 Telegram、Webhook、邮件、企业微信、钉钉、飞书或 Bark 渠道。

默认冷却 30 分钟，按事件与通知渠道分别计算。恢复通知独立发送一次；失败渠道在后续评估重试，已成功渠道不因其他渠道失败而重复发送。恢复通知失败不阻断事件关闭及下一次异常的自动化。

旧通知订阅配置保持兼容。预警规则通过独立关联表选择渠道，事件详情能查看对应通知的发送结果。

## 采集频率与实际延迟

| 任务 | 默认间隔 | 支持范围 |
| --- | ---: | ---: |
| 规则评估 | 60 秒 | 固定 60 秒 |
| 倍率采集 | 60 秒 | 60～120 秒 |
| 用量、稳定性、IP 采集 | 60 秒 | 60～120 秒 |
| 关联渠道余额采集 | 300 秒 | 300～600 秒 |

仅有对应启用规则时才启动该类预警采集。正在运行的任务跳过重复调度。用量采集只同步增量范围，不执行完整账号快照、主动测速或付费探测；上游用量接口仍按其现有日期分页能力读取，远端请求量取决于当天日志量。

规则连续次数按新采样计算：默认余额规则需要 3 份新余额采样，通常需约 10～15 分钟并加上一轮评估延迟；不会用同一份余额每分钟重复累计。倍率依赖上游真实探测样本及时间戳，重复读取旧缓存不会增加次数。

预警总开关及频率通过 `GET/PUT /api/alerts/settings` 管理。该设置尚未增加单独的前端表单。指标样本保留 8 天，事件及动作记录保留用于审计，通知日志沿用原有清理策略。

## 协议扩展与验证边界

本分支实现 sub2api。`MetricCollector` 提供归一化指标，`AutomationAdapter` 提供实时启用状态、状态版本和写入能力。newapi 后续在站点接入层补充字段映射与接口实现，可以复用规则、状态机、动作审计及通知；本分支不宣称已支持 newapi 远端自动化。

当前验证包括后端全量测试、前端 111 项测试、TypeScript 检查、生产构建及浏览器 16 项交互验收。后端集成测试使用独立 SQLite 与本地 HTTP 服务，浏览器使用独立演示数据库；未对真实站点执行停用或启用。PostgreSQL 的实际数据库迁移和会话锁仍需在部署环境验证。

仓库已有 `lint` 脚本引用 ESLint，但没有安装该依赖，因此本次不能运行该项检查；类型检查、测试和构建正常完成。

功能在独立 worktree 和 `codex/feature-alert-automation` 分支中交付，未合并到主分支。
